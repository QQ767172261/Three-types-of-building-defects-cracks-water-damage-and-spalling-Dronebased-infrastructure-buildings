### 表 3 标签定义（VOC → YOLO 对照）

VOC 的类别名写在 `Annotations/*.xml` 的 `<name>` 字段，转 YOLO 时按同一顺序映射为 class_id：

| class_id | 建议英文名 | 中文 | VOC `<name>` 字段 |
| --- | --- | --- | --- |
| 0 | Crack | 建筑裂纹 | 需以 xml 实际写法为准 |
| 1 | Water_Penetration | 水浸 | 需以 xml 实际写法为准 |
| 2 | Spalling | 剥落 | 需以 xml 实际写法为准 |

转成 YOLO 后的 `data.yaml`：

```
path: ./datasets/uav_defect
train: images/train
val: images/val
test: images/test

nc: 3
names:
  0: Crack
  1: Water_Penetration
  2: Spalling
```

> 
> 注意：`names` 的顺序必须和转换脚本里生成的 class_id 一一对应。VOC 原始类名不要直接照抄进 yaml（可能带中文或空格），先用脚本统计出全部 `<name>` 取值，再统一映射。

### 表 4 数据规格与转换

| 项目 | 说明 |
| --- | --- |
| 目录结构 | VOC 标准：`Annotations/`（xml）+ `JPEGImages/`（原图）+ `ImageSets/Main/`（划分 txt） |
| 划分情况 | 原始说明未给出 train/val/test 比例，需按 `ImageSets` 或自行按 7:2:1 切分 |
| 转换方式 | VOC→YOLO 用脚本读 xml 的 `bndbox`，按 `(xmin,ymin,xmax,ymax)` 归一化为 `x_center,y_center,w,h` |
| 分辨率适配 | 4600 与 3700 都不是 32 的整数倍，直接训练会被补齐或缩放 |
| 训练建议 | 高分辨率下裂纹仅占几十像素，整图缩到 640 必然丢失；建议切成 1024 或 640 的重叠切片训练，推理时再拼回 |

### 表 6 三个必须提前处理的点

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| 超高分辨率 | 直接 resize 到 640，裂纹会细到 1–2 像素，模型学不到 | 切片训练（tiling），单块 1024，重叠 20%，训练完做结果拼接去重 |
| 13GB 体积 | 训练 IO 慢、显存换页频繁 | 先离线切片并把切片存为 1024 小图，训练读小图，速度能提 3–5 倍 |
| 水浸类边界模糊 | 湿痕与阴影、污渍难区分，易误检 | 该类别单独看召回；必要时增加负样本（污渍、阴影墙面）抑制误报 |
